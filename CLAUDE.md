# DimVibe — конструктор интерактивных заданий: инструкция для проекта

Живой документ. Здесь только согласованное и явно помеченное как открытое. Всё, что решается, переносится сюда с датой. Полную спецификацию (архив DimVibe Specification Kit v32) не копируем: сюда попадают только принципы работы модулей и их особенности.

## 1. О проекте и работе с владельцем
- Проект строим с нуля. Старый прототип Google AI Studio — только визуальный и функциональный референс, его код не переносим.
- Владелец — не программист. Код пишет Claude в Claude Desktop, владелец проверяет результат.
- Говори простым языком. Термин, если он нужен, поясни одной фразой.
- Работай маленькими шагами. Перед шагом скажи, что сделаешь, каким будет результат и как его проверить. Файлы меняй только после согласования.
- Не принимай решений за владельца. Развилку покажи в виде 2–3 вариантов с плюсами и минусами и дай рекомендацию; выбор оставь ему.
- Если данных не хватает или факт не проверен, скажи об этом прямо. Условия бесплатных тарифов и сервисов проверяй по актуальной документации.
- Не объявляй готовым то, что не проверено в работе.

## 2. Текущий режим работы (решения владельца)
- Пока каждый преподаватель работает сам у себя: без общих аккаунтов и общей библиотеки. Модель с аккаунтами и личными библиотеками остаётся целевой на будущее.
- Внутри одного задания можно смешивать разные режимы ответа (например, в одном тексте часть пропусков с банком слов, часть с вводом вручную). Это решение владельца; оно заменяет утверждённое в архиве правило «один режим на упражнение» до тех пор, пока архив не обновлён.
- Прототип не переносим по коду, но его названия модулей и внешний вид — ориентир.
- Нужны: переключение светлой и тёмной темы, система тегов, вид папок, отображаемые названия модулей (менять можно позже, это не принципиально).

## 3. Принципы архитектуры
1. **Независимые модули.** Каждый тип задания имеет свой редактор, свой плеер и свою логику. Изменение одного модуля не должно ломать другие.
2. **Общее ядро — только общее.** Общее: редактор (вкладки Содержимое, Дизайн, Поведение, Публикация), жизненный цикл прохождения (проверки, баллы, перезапуск), публикация. Модули не дублируют эту логику.
3. **Общий движок пропусков** (Gap Engine) для модулей с пропусками. Он отвечает только за разметку и операции с пропусками. У каждого пропуска устойчивый ID, он не зависит от текста.
4. **Короткий код встраивания.** В LearnWorlds вставляется ссылка на упражнение по ID, а не весь проект. Данные и медиа в код не вшиваются (ни картинки, ни аудио в base64).
5. **Черновик и публикация разделены.** Черновик не виден ученику, пока автор не нажмёт «Опубликовать». Опубликованная версия неизменяема. Редактирование черновика не меняет уже работающее упражнение.
6. **Прохождение ученика не сохраняется.** Ответы ученика живут в памяти текущего прохождения. Обновление страницы начинает новое прохождение.

## 4. Проверки и баллы (общие правила)
- Проверка — один запуск оценки. Обычно 3 проверки на прохождение, при 6+ оцениваемых единицах — 5; у отдельных модулей правило другое (см. ниже). По умолчанию 5, в настройках можно 1–5.
- Неполный или некорректный ответ проверку не расходует.
- Баллы: обычно 1 балл за каждый верный оцениваемый элемент; у некоторых модулей — за задание целиком.
- «Начать заново» сбрасывает прохождение ученика, но не черновик автора.

## 5. Модули: принципы и особенности

### 5.1 Fill Blanks (пропуски) — первый модуль
- Два вида текста: **отдельные предложения** (каждое — самостоятельное задание, допускается одно предложение) и **связный текст**. Пропуски в тексте создаются выделением слова или фразы.
- Несколько пропусков в одном предложении — допускаются. Максимум **10 пропусков** на задание (контролирует редактор).
- Режимы ответа: **Free Input** (ввод вручную), **Word Bank** (банк слов), **Dropdown** (выпадающий список). Режимы можно смешивать внутри задания (решение владельца, см. раздел 2).
- Текст, пропуски, ответы, подсказки и озвучка общие для всех режимов. Переключение режима не удаляет данные других режимов.
- Сравнение ввода: без учёта регистра, обрезка краевых пробелов, нормализация лишних пробелов. Альтернативные ответы добавляются явно.
- **Word Bank:** банк может наполняться автоматически из правильных ответов пропусков или вручную. Ловушки (неверные слова) добавляются кнопкой `+ Добавить слово`. Слово выбирается нажатием, затем нажатием на пропуск (основной способ); перетаскивание — дополнительный. Использованное слово остаётся в банке на своём месте, приглушённое, и возвращается при очистке пропуска. Правильные ответы, закреплённые после проверки, не перемещаются.
- **Dropdown:** варианты всех пропусков собираются в общий пул (основные ответы всех пропусков, явно добавленные альтернативы, общие ловушки). Правильность определяется только по ответам конкретного пропуска, а не по всему пулу. Минимум 2 варианта, из них хотя бы один верный и один неверный; рекомендуется 3–5; при более 8 — предупреждение, без блокировки. Варианты перемешиваются при новом прохождении, внутри прохождения порядок стабилен.
- Визуальные стили пропусков: 3 варианта (в архиве — 4 типа пропусков, 2 вида линий, полужирный ввод, угловые индикаторы; уточнить при проектировании).

### 5.2 Image to Gaps (картинка с пропусками) — отдельный модуль
- Не режим Fill Blanks. Использует тот же Gap Engine.
- Ученик ставит слова-ответы на области картинки: нажатием или перетаскиванием.
- Банк ответов с дистракторами (неверными). Проверка, неверные возвращаются в банк.
- Изображение: режимы contain/cover. Картинка берётся из общей медиатеки с повторным использованием.

### 5.3 Mini Dialogues (диалоги, модуль 22)
- Задание в виде переписки: реплики как пузыри, у каждого говорящего имя, сокращение или аватар, стабильная сторона/цвет.
- В тексте реплик — пропуски. Ответы: ввод, банк слов или выпадающий список (в архиве — выбор одного режима на задание; уточнить с учётом решения о смешивании).
- Одна общая проверка на всё задание. Без ветвления, без ролевой игры в реальном времени, без записи голоса ученика, без ИИ-генерации в первой версии.
- Говорящие различаются не только цветом: у трёх и более говорящих нужны подписи или аватары.

### 5.4 Matching (сопоставление)
- Два столбца; верные пары уходят в зелёную зону решённых, неверные остаются красными и отвязываются для повтора.
- Режимы: Standard (3 или 5 проверок) и Lines (все карточки на месте, линии окрашиваются после одной итоговой проверки).

### 5.5 Ordering (упорядочивание)
- Ученик переставляет элементы в правильном порядке. Порядок перемешивается при новом прохождении.
- Одна проверка. Дубликаты элементов блокируют публикацию.

### 5.6 Categories / Sorting (категории)
- Категории создаёт автор, карточки относятся к категориям. Каждая карточка имеет ровно одну правильную категорию, в категории может быть несколько карточек.
- Ученик раскладывает нажатием или перетаскиванием. Верные карточки фиксируются, неверные возвращаются в банк при промежуточных проверках. 1 балл за карточку.

### 5.7 Timeline (хронология)
- События в правильной хронологической последовательности, подписи дат — любые.
- Одна итоговая проверка на прохождение. 1 балл за событие в правильной позиции.
- Одинаковые даты разрешены с предупреждением; визуально одинаковые карточки блокируют публикацию.

### 5.8 Word Scramble / Sentence Builder
- Из рассыпанных слов или фрагментов собрать фразу. 1 балл за полностью правильное задание (не за каждое слово).
- Одна общая проверка.

### 5.9 Splice (слова из слогов/частей)
- Режимы: одно слово или «мозаика» из нескольких слов. Сложность Easy / Medium / Hard (Medium по умолчанию).
- Одна общая проверка, 1 балл за правильное слово.

### 5.10 Остальные модули (Multiple Choice, True/False, Odd One Out, Select Title, Color Coding, Mistake Mode, Flashcards, Hotspot, Label the Diagram, Vocabulary, Prepositions, Essay, Word Search и др.)
Принципы для них ещё не перенесены в эту инструкцию. Переносим по одному, по мере работы с каждым модулем, после согласования.

## 6. Медиа и озвучка
- Картинки и аудио хранятся вне кода, в медиатеке. В задании хранится ссылка или ID файла.
- Аудио: прикрепить файл или сгенерировать; подсказки могут звучать, но без штрафов в первой версии.
- Изображение в инструкции: загрузить файл или указать ссылку.
- Публичные ссылки на медиа нужны для iframe; где именно лежат файлы — открытый вопрос (раздел 8).

## 7. Публикация и LearnWorlds
- В LearnWorlds вставляется iframe один раз, потом правки подхватываются через «Опубликовать изменения» без замены кода.
- Ученик видит только плеер, не редактор.
- Снятие с публикации показывает понятное сообщение «недоступно»; повторная публикация возвращает ссылку.
- Обязательная проверка до масштабирования (LearnWorlds iframe acceptance test): первичная вставка; обновление после публикации без смены кода; независимость уже открытого прохождения; медиа через iframe; высота 600 px на десктопе и телефоне; снятие и возврат публикации; черновик не доступен по публичной ссылке; свежая версия при новом открытии.
