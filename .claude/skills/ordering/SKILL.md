# Ordering (девятый модуль)

Спецификация: `docs/spec/04_MODULES/ORDERING.md` (OR-01…OR-04, модуль 08 архива), решения D-064…D-069 в `docs/spec/DECISIONS.md`, приёмка OR-AC-01…18 в `docs/spec/07_DELIVERY/ACCEPTANCE_CRITERIA.md`.

Решения владельца 2026-10-25 («подходят все рекомендации»):
1. До 5 последовательностей в упражнении, все на одной странице друг под другом, у каждой при нескольких — своя необязательная инструкция; проверка общая.
2. Проверка одна, итоговая, как в архиве (D-069): до неё переставлять можно сколько угодно, после — порядок замораживается. Обычные 3/5 проверок с закреплением не используются.
3. После проверки: порядок ученика с ✓ / ✗ на каждом месте (верные зелёные, неверные красные). Подпись «Правильно: …» у неверного места (какой элемент должен там стоять) — только если во вкладке «Поведение» включено «Показывать правильный ответ» (решение владельца 2026-10-25; по умолчанию выключено, в файле `showAnswers: true` только при включённом).
4. Перенос: за ручку ⋮⋮ слева (мышь и палец, на событиях указателя, `modules/ordering/drag.js`) плюс стрелки ↑↓ справа. Касание карточки вне ручки прокручивает страницу.
5. Вид — только столбиком, с номерами мест. Вид «в строку» (собрать предложение из слов) — возможный отдельный этап позже.
6. Картинки и звук: **этап 2** (ещё не сделан) — элемент может быть текстом, картинкой или картинкой с подписью; звук у последовательности. Только через общие `MediaUI.imageControl` / `MediaUI.picker`. Этап 1 (сделан 2026-10-25) — только текст.
- Лимиты: от 2 до 10 элементов в последовательности (новая — 3 пустых поля), до 5 последовательностей, элемент до 300 символов.

## Что делает ученик
Видит элементы перемешанными, столбиком, у каждого номер места. Тянет за ⋮⋮ (элемент едет за пальцем, соседи раздвигаются, у края окна список прокручивается сам) или жмёт ↑↓. Строка внизу до проверки: «Расставьте элементы по порядку. Проверка одна.» Нажимает «Проверить» один раз — ручки и стрелки исчезают, места окрашиваются, итог «Результат: N из M (%)». Кнопка становится «Начать заново».

## Проверка и баллы
- Единица общего хода — место в последовательности (ID единицы `q1:0`, `q1:1`…): `answer` — ID элемента, который должен там стоять, `value` — ID поставленного (заполняется при проверке).
- 1 балл за каждый элемент на своём месте; считается один раз. Плеер даёт `maxChecks() = 1` и свой `check()` → `{done: true}`.
- «Не заполнено» не бывает: порядок есть всегда.
- Перемешивание: при каждом новом прохождении и «Начать заново»; стартовый порядок никогда не совпадает с правильным (до 20 попыток, потом сдвиг на одно место). Отключить нельзя, ручного стартового порядка нет. В предпросмотре редактора порядок держится, пока набор ID элементов тот же (как у Matching), чтобы карточки не прыгали при правках.
- «Начать заново» без вопроса, пока ученик ничего не двигал (`started()`).

## Редактор
Порядок полей сверху вниз — правильный ответ; перестановка (ручка ⋮⋮ или ↑↓) меняет ответ, отдельного выбора ответа нет. Строка: ручка, номер, поле, выше / ниже / удалить (не меньше 2 полей). «+ Элемент» до 10. Одинаковые элементы в одной последовательности сразу подсвечиваются красной рамкой. При нескольких последовательностях: заголовок «Последовательность N», выше / ниже, копия (новые ID последовательности и элементов), удаление с подтверждением, если не пустая; поле своей инструкции. «Поведение»: «Проверок на прохождение: 1» с пояснением (`fixedChecks` + `fixedChecksNote`; текст пояснения ядро берёт из модуля) и выключатель «Показывать правильный ответ» (`behaviorOptions`, поле `showAnswers`). «Дизайн» — общий, макет с флагом `tf`; своих настроек нет.

## Публикация (validate)
Ошибки: нет последовательностей; больше 5; меньше 2 заполненных элементов; больше 10; пустой элемент посередине (пустые в конце не ошибка — в файл не попадают); одинаковые элементы в одной последовательности (без учёта регистра и лишних пробелов; в разных последовательностях можно).

## Файл упражнения
```json
{ "module": "ordering", "format": 1, "showAnswers": true,
  "sequences": [{ "id": "q1", "instruction": "Put the numbers in order",
                  "items": [{ "id": "i1", "text": "Wake up" }, { "id": "i2", "text": "Brush teeth" }] }] }
```
Порядок `items` — правильный порядок. `instruction` пишется только при нескольких последовательностях и если не пустая. ID элементов уникальны во всём упражнении. При загрузке повтор ID получает новый, недостающие элементы — пустые поля.

## Файлы
`modules/ordering/`: `drag.js` (`OrderingDrag` — перенос за ручку, общий для редактора и плеера; меняет местами соседей, а не сам элемент, иначе теряется захват указателя), `editor.js` (`OrderingEditor`), `editor.css`, `player.js` (`OrderingPlayer`), `player.css`. Классы с приставкой `or-`; элементы плеера — `.card.or-item` (Comic рисует им контур), у ручки и стрелок контур Comic скрыт.

## Не проверено
Настоящий палец на телефоне (перетаскивание проверено мышью; у ручки `touch-action:none`), Safari/Firefox, LearnWorlds iframe; владельцем — ещё нет.
