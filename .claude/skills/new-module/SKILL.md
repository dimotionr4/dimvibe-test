# Новый модуль DimVibe: чек-лист

Собрано 2026-10-24 по шести готовым модулям (Fill Blanks, Image to Gaps, True / False, Multiple Choice, Matching, Mistake Mode). Образец для копирования — **Mistake Mode** (`modules/mistake-mode/`): самый новый и использует все крючки. Если код ядра с тех пор поменялся, верить коду, а этот файл поправить.

## 1. До кода: согласовать с владельцем
1. Прочитать правила модуля: раздел в `docs/MODULE_NOTES.md` и файл архива `docs/spec/04_MODULES/<МОДУЛЬ>.md` (только его, не весь архив).
2. Показать владельцу короткий план: что ученик делает, как проверяется, сколько баллов, лимиты (сколько элементов), что входит в этап 1. Развилки — 2–3 варианта с рекомендацией. Владелец часто отвечает «все рекомендации» — тогда записать, какие именно.
3. Этапы, как у прежних модулей: **этап 1** — только текст, редактор + плеер + публикация; дальше — картинки и звук, настройки «Дизайна», особые режимы. Каждый этап — отдельное согласование и отдельная проверка.

## 2. Файлы модуля
`modules/<папка-через-дефис>/`: `editor.js`, `editor.css`, `player.js`, `player.css` (при необходимости свой общий файл, как `tokens.js` у Mistake Mode). ID модуля в данных — через подчёркивание (`mistake_mode`), папка — через дефис (`mistake-mode`). Каждый файл — одна глобальная константа, замкнутая функция `(() => { …; return {…}; })()`.

### Редактор: `const <Имя>Editor`
| Функция | Обязательна | Что делает |
|---|---|---|
| `create(layout)` | да | поля нового черновика (без `id`, `title` — их ставит ядро) |
| `demo(layout)` | да (с 2026-10-25) | демо-пример для демо-режима «Настроек»: `{...create(layout), …}`, заполненный так, чтобы были видны все возможности модуля (несколько заданий, правильные ответы, пояснения, картинки и звук из `DimDemo.IMG` / `DimDemo.AUD`, `core/demo.js`); `instruction: DimDemo.instruction('текст')`. Должен проходить `validate` без ошибок и предупреждений. Пометки на словах — по номеру слова из своего деления на слова |
| `render(container, draft, onSave)` | да | вкладка «Содержимое» под общей инструкцией; после каждой правки вызывать `onSave()` — тогда работают автосохранение, Undo/Redo и предпросмотр |
| `exportData(draft)` | да | чистый файл для ученика: `{module, format, …}` без пустых элементов |
| `validate(draft)` | да | `{errors, warnings}` — ошибки блокируют публикацию, предупреждения нет; тексты по-русски, с номером элемента |
| `load(file)` | да | файл упражнения → черновик; старые файлы и неверные поля не ломают, а получают значения по умолчанию; при пустом файле — `throw new Error('понятная причина')` |
| `unitCount(draft)` | желательно | число оцениваемых единиц для «авто» числа проверок (3 при 1–5, 5 при 6+) |
| `designOptions(draft)` | нет | настройки вкладки «Дизайн»: `[{field, label, value, names, icons}]`, ядро рисует их само, поле лежит в черновике |
| `behaviorOptions(draft)` | нет | выключатели вкладки «Поведение»: `[{field, label, value, help}]` |
| `fixedChecks(draft)` | нет | режим сам задаёт число проверок (0 — выбирает автор) |

Картинки и звук в редакторе — только через общие `mediaPicker(...)` / `MediaUI.imageControl` (`core/mediabar.js`), свои загрузчики не писать. Подсказки «?» — `helpIcon(...)`.

### Плеер: `const <Имя>Player`
Модуль работает внутри общего хода прохождения `index.html` (шапка, инструкция, проверки, итог, сброс ↻) и пользуется его глобальными `data`, `gaps`, `finished`, `note`, `checksUsed`, `maxChecks`, `render()`, `norm()`, `shuffle()`.
| Функция | Обязательна | Что делает |
|---|---|---|
| `units()` | да | список единиц ответа (ложатся в `gaps`); у каждой `value`, `locked`, `state` (`ok`/`bad`/`missing`/null) |
| `reset()` | да | своё состояние нового прохождения (перемешивание — здесь, один раз) |
| `render(root)` | да | нарисовать задание в `root` |
| `instant()` | да | `true` — ответ засчитывается сразу, без кнопки «Проверить» (показ «по одному») |
| `missingNote(n)`, `goMissing()` | да, если общая проверка | текст «заполните ещё n» и переход к первой незаполненной |
| `check()` | нет | своя проверка: вернуть `{note}` (проверку не тратит) или `{done}` |
| `status()`, `percent(pct)`, `started()`, `maxChecks()` | нет | своя строка результата, поправка процента, «ученик уже начал», своё число проверок |

Общие правила хода (`CLAUDE.md`, раздел 4): неполный ответ проверку не тратит, верное закрепляется, «Начать заново» перемешивает заново, внутри прохождения порядок стабилен. Сравнение текста — общий `norm()`.

## 3. Куда подключить (все места)
**`editor.html`:**
- `<link>` на `editor.css` и `<script>` на `editor.js` (с `?v=1`) рядом с другими модулями;
- `MODULES` — добавить `<id>: <Имя>Editor`;
- окно «Какое упражнение создать?» (`#modPick`) — кнопка `data-mod="<id>"`;
- если у модуля нет выбора «предложения / связный текст», добавить `id` в **три** списка: `pickModule` (одна кнопка «Создать»), разбор `?new=` в конце скрипта (`createDraft('statements', mod)`), вызов `designMock({ tf: … })` в `renderDesign` (макет «Дизайна» рисует кнопки вместо пропуска; при своём макете — свой флаг, как `mt`, `mm`);
- поднять `ASSET_V` на 1.

**`index.html`:** `<link>` на `player.css`, `<script>` на `player.js`; добавить ветку в `unitPlayer()`; если в плеере есть карточки с пометкой «не заполнено» — класс в строке поиска `document.querySelector('.gap.missing, …')` в `check()`.

**`home.html`:** в `MODS` поставить `ready: true` (и описание), значок — в `ICON`.

**`exercises.html`:** в `MODS` — `name` и `icon` (тот же значок, что на табло).

## 4. Проверка перед «готово»
Проверять в браузере Claude по локальному серверу (`python -m http.server` из папки проекта; `file://` не загружает файлы упражнений):
- создание с табло (`home.html` → карточка модуля) и из окна «Какое упражнение создать?»;
- редактор: добавить, изменить, удалить, лимиты, Undo/Redo, ошибки блокируют «Опубликовать»;
- предпросмотр обновляется сам; плеер: неполный ответ не тратит проверку, верно/неверно, конец, «Начать заново»;
- Classic и Comic, светлая и тёмная темы, ширина 375 px без прокрутки вбок;
- выгрузка файла и обратная загрузка («Открыть файл») дают тот же черновик;
- старые модули не сломались (хотя бы Fill Blanks открыть и пройти).
Честно писать, что не проверено: настоящий палец на телефоне, Safari/Firefox, загрузка файлов (нужен вход владельца), LearnWorlds.

## 5. Записать
- skill модуля `.claude/skills/<папка>/SKILL.md`: правила из `MODULE_NOTES.md` + решения владельца + формат файла; раздел модуля из `docs/MODULE_NOTES.md` убрать (заменить ссылкой на skill);
- `CLAUDE.md`, раздел 5 — строка со ссылкой на skill;
- `HANDOFF.md` — строка в таблице модулей; подробная запись шага — в конец `docs/HISTORY.md`;
- подпись коммита для владельца.

## Уроки прежних модулей
- Карточки плеера не наследуют высокий интервал строк `.card` (он под значки пропусков): давать свой класс `.card.<xx>-card` с `line-height: 1.5`.
- Скрываемым элементам с `display:…` нужно правило `[hidden]{display:none}`.
- Предпросмотр пересобирается после каждой правки: не перемешивать заново, пока состав элементов тот же (иначе карточки «прыгают», как было в Matching).
- HTML5-перетаскивание не работает пальцем: на телефоне оставлять кнопки или делать перенос на событиях указателя.
- Версии `?v=` поднимать при каждой правке файла; при правке из PowerShell не добавлять BOM.
