# Fill Blanks (пропуски) — первый модуль

Подробная спецификация: `docs/spec/04_MODULES/FILL_BLANKS.md` (открывать только нужные места). При расхождении приоритет у решений владельца в `CLAUDE.md`.

- Два вида текста: **отдельные предложения** (каждое — самостоятельное задание, допускается одно предложение) и **связный текст**. Пропуски в тексте создаются выделением слова или фразы.
- Несколько пропусков в одном предложении — допускаются. Максимум **10 пропусков** на задание (контролирует редактор).
- Режимы ответа: **Free Input** (ввод вручную), **Word Bank** (банк слов), **Dropdown** (выпадающий список). Один режим на всё упражнение, его выбирает преподаватель; смешивать режимы внутри задания не нужно (решение владельца, см. раздел 2 `CLAUDE.md`).
- Текст, пропуски, ответы, подсказки и озвучка общие для всех режимов. Переключение режима не удаляет данные других режимов.
- Сравнение ввода: без учёта регистра, обрезка краевых пробелов, нормализация лишних пробелов. Альтернативные ответы добавляются явно.
- **Word Bank:** банк может наполняться автоматически из правильных ответов пропусков или вручную. Ловушки (неверные слова) добавляются кнопкой `+ Добавить слово`. Слово выбирается нажатием, затем нажатием на пропуск (основной способ); перетаскивание — дополнительный. Использованное слово остаётся в банке на своём месте, приглушённое, и возвращается при очистке пропуска. Правильные ответы, закреплённые после проверки, не перемещаются.
- **Dropdown:** варианты всех пропусков собираются в общий пул (основные ответы всех пропусков, явно добавленные альтернативы, общие ловушки). Правильность определяется только по ответам конкретного пропуска, а не по всему пулу. Минимум 2 варианта, из них хотя бы один верный и один неверный; рекомендуется 3–5; при более 8 — предупреждение, без блокировки. Варианты перемешиваются при новом прохождении, внутри прохождения порядок стабилен.
- Визуальные стили пропусков: 3 варианта (в архиве — 4 типа пропусков, 2 вида линий, полужирный ввод, угловые индикаторы; уточнить при проектировании).

## Формат файла упражнения (format 2, 2026-10-22)
```json
{
  "id": "ex-001", "module": "fill_blanks", "format": 2, "published": true,
  "title": "…", "layout": "sentences", "mode": "word_bank",
  "items": [{ "id": "s1", "parts": ["The bartender ", {"gap": "g1"}, " the drink."] }],
  "gaps": { "g1": { "answer": "poured", "alternatives": [], "hint": "" } },
  "distractors": ["cup"]
}
```
- `layout`: `sentences` (отдельные предложения) или `text` (связный текст). Вид выбирается один раз при создании упражнения и потом не меняется (решение владельца, 2026-10-22). В связном тексте абзацы — это те же `items`; плеер показывает их одной карточкой, в предложениях — по карточке на каждый item.
- `behavior.checks`: число проверок, `"auto"` или 1–5. Автоматически: 3 при 1–5 пропусках, 5 при 6 и больше (по числу пропусков в файле). Файлы без `behavior` считаются автоматическими.
- Ход прохождения в плеере (общие правила Behavior Core, см. `docs/spec/03_CORE/BEHAVIOR_CORE.md`): неполный ответ проверку не тратит и отмечает пустые пропуски; верные ответы после проверки закрепляются (✓), неверные остаются редактируемыми (✗), правка снимает отметку; конец — при 100% или когда проверки закончились, дальше ввод закрыт, главная кнопка «Начать заново»; внизу «Заполнено N из M», потом «Верно X из M · Проверок осталось K», в конце процент. Сброс — кнопка ↻ в шапке (с коротким подтверждением, если ответы уже есть). Сравнение: NFC, без регистра, лишних пробелов и конечных `. , ? !`.
- `design.accent`: цвет упражнения — ключ из набора `core/design.js` (`violet`, `blue`, `teal`, `green`, `orange`, `pink`); неизвестный или отсутствующий ключ → `violet`. Набор общий для редактора и плеера, меняется только в этом файле (и там же поднимается `?v=` подключения). Красный и зелёный результата — системные. В тёмной теме на акценте тёмный текст (`--on-accent`).
- `instruction`: `{title, text}`, общий для модулей блок над заданием; в тексте `**жирный**`, `*курсив*`, новая строка — новый абзац (разбор — `core/richtext.js`, HTML из текста не выполняется). `design.showInstruction` (по умолчанию `true`): `false` скрывает инструкцию, но не удаляет. У ученика она развёрнута, может сворачиваться; «Начать заново» разворачивает снова. Изображение инструкции — `instruction.image` = `{url, alt, size: small|medium|large, align: left|center|right}`: пока только ссылка `https://` (адрес проверяет `safeImageUrl` в `core/richtext.js`, неправильная ссылка блокирует публикацию); `design.showImage` (по умолчанию `true`) скрывает картинку независимо от текста. Ширина картинки: small 100 px, medium 160 px, large 240 px (высота не больше 240 px; значения лежат в `instructionImageEl`, `core/richtext.js`, и подбираются по месту). При `left`/`right` текст обтекает картинку сбоку, на узком экране боковая картинка не шире 45% блока; при `center` она над текстом. Если картинка не загрузилась, ученик видит `alt`. Загрузка файла и звук (2026-10-23): хранилище Firebase Storage (`core/media.js`), вход Google только у владельца. Картинка: `instruction.image = {media | url, alt, size, align}`, где `media` — путь `media/<ID упражнения>/img-xxxxxxxx.webp` в бакете; адрес собирает `mediaUrl()`. Звук: `instruction.audio = {media}`, у пропуска `gaps[id].audio = {media}` (озвучка слова — значок динамика справа сверху, не зависит от проверок) и `gaps[id].hintAudio = {media}` (звук в окне подсказки; подсказка может быть только звуковой, `hint` пуст). Озвучка предложения (абзаца) целиком: `items[i].audio = {media}`, значок динамика в начале строки. Файлы: картинки JPEG/PNG/WebP до 2 МБ, звук MP3/M4A/OGG/WAV до 10 МБ; опубликованные файлы не перезаписываются и не удаляются. Состояние — в `HANDOFF.md`, подробности шагов — в `docs/HISTORY.md`.
- `design.gap`: оформление пропуска — `{shape: line|frame|pill|free, dashed, width: auto|narrow|wide, numbered}` (набор и проверка — `normalizeGapDesign` в `core/design.js`, стили — `core/gap.css`, общие для плеера и образцов в редакторе; `?v=2` у `design.js` и `gap.css`). «Прерывистая» работает только у линии и рамки (в черновике выбор сохраняется, у плашки и свободной формы не применяется). Нумерация по умолчанию выключена, текст внутри пропуска полужирный (600). Ширина — минимальная (64 / 90 / 180 px): длинное слово в банке растягивает пропуск. В режиме ввода пропуск растёт по мере набора текста и сжимается при стирании (`fitInput` в `index.html`: ширина по тексту, не меньше значения из дизайна и не шире строки; совсем длинный ответ прокручивается в поле) — по замечанию владельца, раньше текст обрывался. В выпадающем списке «Авто» ширина по самому длинному варианту в списке (одинаковая у всех пропусков и не прыгает при выборе), «Узкая» и «Широкая» фиксированы, длинное слово там обрезается. Старый файл без `gap` — сплошная линия, авто, без номеров. Вид Classic; Comic — отдельный шаг.
- Стиль Comic (проба, 2026-10-23): `design.style` = `classic` (по умолчанию) или `comic`, `design.comicLine` = `accent` (по умолчанию) или `black`. Включается классами `style-comic` и `line-black` на `<html>`; стили — `core/comic.css` (`?v=7`), кривые строит `core/rough.js` (`?v=3`, `roughen()` вызывается после каждой перерисовки и следит за размером элементов). Контур и заливка — обычный SVG-рисунок `<svg class="rough">` внутри самого элемента (под содержимым), форма зависит только от «ключа» элемента (номер пропуска, слово), поэтому при нажатиях контуры не меняются. Толщина — `design.comicWidth` = `thin` (2 px), `normal` (3 px, по умолчанию), `thick` (4,5 px); в пробе `?lw=thin|thick`. Прежние версии отвергнуты по замечаниям владельца: SVG-фильтр смещения пикселей давал «лесенку», а маска слоя ::before сместилась у владельца и перерисовывалась с новой формой при каждом нажатии. Номер пропуска — отдельный элемент `.gap-num`. Шрифт Comic: Blogger Sans (`fonts/blogger-sans/*.woff`, четыре начертания: обычное, курсив, жирное, жирный курсив), подключён в `core/comic.css` (`?v=10`) и грузится только при включённом Comic. Лицензия CC BY-ND 4.0: файлы нельзя изменять (брать готовые WOFF из архива автора, не обрезать и не конвертировать), рядом лежит `CREDITS.txt`, в редакторе слева внизу строка с авторством. Латиница и кириллица есть, грузинские буквы и значки ✓ ✗ ↻ идут из запасных шрифтов. Предыдущий шрифт Bubble Sans убран (не было жирного, рисовал строчные заглавными). После загрузки шрифта плеер заново подгоняет поля ввода и контуры (`afterFontsLoaded` в `index.html`). Выбор стиля — в редакторе: кнопки Classic/Comic вверху на любой вкладке и блок «Стиль» во вкладке «Дизайн» (цвет контура, толщина, образцы в выбранном стиле). Для пробы без редактора в ссылке нужен признак `probe=1`: `?probe=1&style=comic&line=black&lw=thin&shape=pill&dashed=1&num=1&width=wide`. Проверено только в браузере на движке Chromium; в Safari и Firefox вид проверить на владельце.
- `design.page` (шаг 5 «Макет»): `{width: compact|standard|wide, density: compact|comfortable|loose, background: plain|backdrop|card}`; по умолчанию `standard`, `comfortable`, `plain`. Набор и проверка — `normalizePage` в `core/design.js` (`?v=4`); применяет `applyLook` в плеере классами на `<html>` (`width-compact|wide`, `dens-compact|loose`, `bg-backdrop|card`, переменные `--content-w`, `--pad`, `--card-pad`, `--card-gap`, `--card-lh` в `index.html`). Ширина колонки: компактная 560 px, стандартная 800 px (ограничение заметно только на окнах шире 800 px), широкая — на всё окно; относится к шапке, тексту и нижней панели. «Подложка» — оттенок акцента под текстом, «Карточка» — рамка вокруг всего упражнения (класс `panel` на `#root`, в Comic рисуется от руки).
- `design.check` (шаг 6): `{variant: filled|outline|soft, align: right|left|center}`, по умолчанию `filled`, `right`. Набор — `normalizeCheck` в `core/design.js` (`?v=5`), стили нижней панели — `core/check.css` (`?v=1`, общие для плеера и образца в редакторе), классы на `<html>`: `chk-outline|soft`, `chk-left|center`; в Comic свои правила в `core/comic.css` (`?v=12`). Блок результата `#score`: до первой проверки обычный текст «Заполнено N из M»; после проверки в рамке «Верно: X из M · Неверно: Y · Проверок осталось: K»; в конце «Результат: X из M (P%)» и полоса с процентом; предупреждение о пустых пропусках тоже в рамке. Подпись внутри — `#scoreText` (не перезаписывать `#score` целиком: там нарисованный контур Comic). «По центру» на узком экране растягивает кнопку на всю ширину.
- Значки по углам контура пропуска (по утверждённому описанию `GAP_STYLES_AND_INDICATORS.md`): слева сверху номер (18 px), справа сверху зарезервировано под озвучку, справа снизу подсказка (22 px, нажимаемая область ~42 px, кнопка лежит внутри элемента пропуска), слева снизу результат ✓/✗ (28 px, крупнее остальных; рисуется в `::after`). Стили — `core/gap.css` (`?v=3`). Для значков высота строки в карточке 3,5.
- Подсказки (поле `hint` пропуска): значок есть только у пропусков с подсказкой, на которые ещё нет верного ответа. До второй завершённой проверки — замок (нажатие объясняет, когда откроется), после — лампочка с всплывающим окном, которое не выходит за края экрана. Баллы и проверки не тратятся. При одной проверке подсказки остаются закрытыми (в правилах Behavior Core это нерешённый вопрос политики).
- Не сделано: показ верных ответов на последней проверке (в правилах Fill Blanks не описан), перетаскивание слов, озвучка подсказок.
- Кнопки переключения режимов в плеере видны только в предпросмотре (`?preview`); ученик режим не меняет.
- `mode`: `word_bank`, `dropdown` или `typing` — режим всего упражнения (выбирает преподаватель).
- `parts`: куски текста (строки) и пропуски (`{"gap": ID}`). ID пропуска постоянный и не зависит от текста.
- Банк слов: основные ответы + `distractors` (альтернативы в банк сами не попадают). Выпадающий список: основные ответы + альтернативы + `distractors`, без повторов.
