# Mistake Mode — модуль 07

**Статус:** APPROVED DESIGN · 2026-10-15 · MM-01–MM-04. **Реализация не поручена Codex.**

## Назначение и приоритет решений
Ученик самостоятельно находит неверные **отдельные слова** в обычном тексте. Для каждой ошибки преподаватель может дополнительно потребовать письменное исправление. Одна ошибка = максимум 1 балл.

Поздние утверждённые уточнения **заменяют** ранние планы о двух режимах «Fix/Find», глобальном переключателе «Найти / Найти и исправить», выделении фраз, диапазонов и знаков препинания как самостоятельных объектов. Не считать эти старые варианты действующими требованиями. Согласованы MM-01 A–D (один модуль, несколько текстов, общий подход к разметке) в той части, которая не противоречит поздним уточнениям; MM-02 A–E (уточнение) и F–K; MM-03 A–E (позднее уточнение) и F–J (финальная редакция); MM-04 A–F.

## Author Studio
- Один единый тип упражнения без режима. Одно или несколько текстовых заданий, компактные раскрывающиеся панели; создание, изменение порядка, дублирование и удаление через Editor Core. Дублирование создаёт новые идентификаторы текста и пометок.
- Преподаватель вводит текст, затем помечает **отдельное существующее слово** как ошибку. Поддерживается несколько ошибок на текст, каждое вхождение слова получает свой стабильный `errorId`, в том числе повторяющиеся слова. Отметки не перекрываются. Многословные диапазоны и самостоятельное выделение пунктуации не входят в объём.
- У каждой ошибки есть `requiresCorrection` (по умолчанию false), основной вариант правильного исправления и допустимые альтернативы, а также необязательное пояснение. Исправление может содержать несколько слов. Поля исправлений видимы в Author Studio лишь при активном `requiresCorrection`. Выключение опции **не удаляет** ранее введённые ответы.
- Исходный текст всегда содержит неправильные слова; отметки и правильные исправления не отображаются ученику заранее.
- При редактировании текста сохранять связи с достоверно оставшимися вхождениями; неоднозначные или повреждённые отметки требуют ручной повторной разметки. Не переадресовывать ошибку молча к другому одноимённому слову. Удаление отметки сохраняет исходный текст.
- Черновики с незавершёнными данными допустимы. Для публикации необходим как минимум один текст; у **каждого публикуемого текстового задания** должен быть непустой текст и хотя бы одно корректно размеченное слово; при `requiresCorrection=true` нужен непустой основной правильный вариант; повреждённая разметка блокирует публикацию. Пояснения и альтернативы необязательны.

## Student Player
- Ученик видит непрерывный обычный текст **без предварительной подсветки**, нажимает на слово для отметки и повторно — для снятия. Каждое слово выбирается отдельно, включая несколько независимых ошибок в одном тексте; не нужны выбор диапазона, кнопка «Отметить», системное выделение браузера или постоянные рамки.
- Если хотя бы одна размеченная ошибка **данного текстового задания** требует исправления, одинаковое поле исправления предлагается для **каждого выбранного учеником слова**, включая правильные слова, ошибочно отмеченные учеником; иначе полей нет. Пустые поля не блокируют общую проверку и не должны раскрывать, где действительно нужна коррекция. Преподавательские флаги и правильные ответы скрыты до допустимого момента раскрытия.
- Одно или несколько текстовых заданий, отображение по одному / все тексты, по умолчанию по одному; навигация сохраняет отметки и введённые ответы. Текст читабелен, выбор слов доступен с клавиатуры, мыши и касания на телефоне/планшете/узком iframe. Поля размещаются под текстом и остаются доступными при открытой мобильной клавиатуре.
- Исправление у выбранного слова может состоять из нескольких слов; исходная выбираемая единица при этом остаётся одним словом.

## Проверка, баллы, защита от угадывания (MM-04 A–E)
- Проверка разрешена после выбора **хотя бы одного слова в упражнении**, а не после угадывания числа скрытых ошибок. Пустые поля исправлений считаются неверными там, где исправления требуются, и не запрещают проверку.
- Каждое правильно найденное слово без `requiresCorrection` даёт **1 балл**. При `requiresCorrection=true` **1 балл** начисляется только за точное совпадение выбранного вхождения и допустимого исправления (основного либо альтернативного); частичных баллов нет.
- Неверно выбранные (на самом деле правильные) слова баллов не приносят, отрицательных баллов нет; **пока остаётся хотя бы одна ложная активная отметка, 100% и успешное завершение недоступны**, даже если все реальные ошибки найдены. Отметка ложного выбора может показываться ученику как неверная после проверки, однако **места пропущенных ошибок до завершения не раскрываются**.
- Правильно обработанные ошибки закрепляются; неверные исправления и ложные отметки остаются редактируемыми до следующей проверки. Правильные отметки с требуемым, но ещё не правильным исправлением не засчитываются и не закрепляются.
- До исчерпания доступных проверок досрочное завершение только при всех правильно обработанных ошибках и отсутствии ложных отметок. После последней проверки итог фиксируется по общему Behavior Core даже при частичном результате; тогда полный разбор показывает реальные ошибочные слова, допустимые правильные исправления и имеющиеся пояснения. Сброс очищает ученические результаты и возвращает исходный текст.
- Использовать общий Behavior Core (1–5 проверок, по умолчанию 5; подсказки по его общим правилам); не создавать независимые счётчики, отдельный score engine или Student Data Storage.
- Примечание к оцениванию: число баллов за правильно обработанные позиции и право на «100% / полностью завершено» — разные проверки: наличие ложного выбора запрещает второе, но не обнуляет уже заработанные баллы.

## Технические границы и приёмка
- Стабильные ID вхождений/ошибок; надёжные привязки после безопасных изменений текста; конфликты разметки не исправляются автоматически угадыванием.
- Разметка лексических слов и связанной с ними пунктуации определяется реализацией токенизации при сохранении семантики единого нажимаемого слова; самостоятельная ошибка в отсутствующем символе вне текущего объёма. Контракты токенизации и сравнения допустимых исправлений следует детализировать перед реализацией, не расширяя текущий UX.
- Специальные критерии MM-AC-01–18 находятся в `07_DELIVERY/ACCEPTANCE_CRITERIA.md`. Editor Core, Player Core, Behavior Core, Publication, Design System и LearnWorlds iframe переиспользуются. Не менять очередность разработки Codex.
