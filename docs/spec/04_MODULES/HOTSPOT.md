# Module 18 — Hotspot (HS-01–HS-04)

**Status:** Functional design complete. Updated HS-01 A–F, HS-02 A–F, HS-03 A–F, HS-04 A–F **explicitly approved** 2026-10-16. HS-03 A–F were explicitly approved together with HS-04; no inference from the intermediate “давай” was required. Documentation only. No Codex task, code change, schema migration or deployment.

## Intent and integration
A responsive learner exercise for locating objects/regions on one image: mark point(s), select authored hotspot zone(s), or independently draw outline(s). Applicable to language, maps, science and diagrams. Uses shared Author Studio (desktop-only), Media Library, Design System Classic/Comic and Compact/Standard, Player Core, versioned publishing and LearnWorlds iframe. Do not assume computer-vision/AI object recognition.

## Two orthogonal dimensions
**Response interaction:** Point | Zone | Outline. One response interaction per individual task; a single exercise may mix tasks/interactions.
**Task pattern:** Find One (one target), Find Multiple (unordered several distinct targets), Find in Order (sequence of individually presented targets). Pattern and interaction are distinct; any compatible combination is permitted. An exercise consists of one source image with reusable authored zones and task definitions. Each task declares its own instruction (optional instructional audio), response interaction, pattern, target zone IDs, per-target feedback, optional hint and options. Target multiplicity is explicit, with each unique target awardable at most once.

## Author Studio: zone library + task list (HS-02)
- Upload/select an image via Media Library. Canvas displays original with an overlay; separate reusable Zone Library stores `zoneId`, human-readable label, shape, normalized geometry in [0,1] source image coordinates and optional instructional metadata. Separate Task records reference zone IDs. Editing zone geometry propagates within draft; dangling references block publish.
- Shape tools: Select/Move, Rectangle, Ellipse and Polygon, Zoom/Pan. Drag resize/reposition, editable polygon vertices, add/remove vertices, numerical positioning, visible/hidden overlays and Undo/Redo. Polygon creation ends on explicit Close or double-click, but must result in a valid simple closed polygon. Desktop-only editor.
- Geometry: valid positive-area rect/ellipse/simple polygon, no self-intersection, coordinates inside source image. Validate zero area, degenerate polygon, outside-image geometry, missing zone and missing reference; save incomplete drafts but block publishing invalid tasks. Bounds/canvas mapping must honor letterboxed contain offsets, transforms, zoom/pan and device pixel ratio.
- One source image's zones can support many Point/Zone/Outline tasks. Find Multiple requires >1 distinct target and distinct response slots; Find in Order defines canonical teacher sequence. Properly copy task/zone IDs on duplication, preserve references on reorder, avoid silently replacing zone labels on task edits.
- Overlap: Point may be inside multiple zones and tests current task target(s); Outline target geometries may overlap; Zone tasks must not publish with ambiguity between simultaneously selectable candidates. Warn for tiny targets and low outline thresholds. If replacement image or aspect/source dimensions changes, request explicit re-verification of all geometries; do not silently assume correspondence.
- Design controls: Marker (default) vs Highlight (where compatible), hide/show boundaries before submission (hidden default), opacity, design tokens, zone indices, correct-zone reveal after completion, Fit/Zoom/Pan; preserve Classic/Comic and Compact/Standard. Precheck highlight may aid guessing; make this a deliberate teacher design choice. Do not leak hidden zone labels or correctness through DOM accessibility metadata or tooltips ahead of check.
- Publish validation: image reachable and safe, at least one task and all target references valid, needed media available, valid contours, positive areas, valid Outline threshold, Zone selectability ambiguity resolved, incomplete/imported resources not accepted without confirmation. Published image/zone/task/design snapshots are immutable; new drafts or edits cannot mutate active sessions.

## Student Player: response interaction (HS-03)
- Student sees instruction and image, not teacher reference overlays by default. Each task announces expected response interaction; modes do not require student to pick a tool except Outline drawing mode where controls are clear. Response positions/contours convert to normalized source-image coordinates before scoring; zoom, pan, orientation and iframe resizing must not distort matches.
- **Point:** learner places one or more movable/removable markers as prescribed. A point on the geometric boundary is accepted within a small explicitly bounded technical tolerance (same across display scales); outside-image/unintended gestures do not create points. Multiple markers cannot award the same target twice. Hit matching must use unique target assignment rather than naive count.
- **Zone:** learner chooses authored interactive region, tap again toggles uncommitted selection; correct zone identity (not pixel color or topmost arbitrary DOM element) is evaluated; zones cannot be ambiguously selectable in published tasks. Precheck Highlight optional; no hidden answer leak via accessibility semantics.
- **Outline:** Polygon Points (add, move, remove vertices, explicitly close, Undo/Clear) or Freehand (pointer/touch/stylus tracing, smoothing with fidelity, explicit resulting closed region). Invalid polygons, open paths, degenerate or self-intersecting shapes require repair *without* spending a check. For multiple targets learner draws required number of contours; compare to target geometries using max-one-to-one matching, not duplicate-credit matching.
- **Outline acceptance:** intersection-over-union (IoU) = area(intersection) / area(union) >= per-task threshold. Teacher-configurable threshold 30–90%, default 65%. Drawn vs authored geometry measured in common normalized source-image space; define consistent deterministic boundary, polygon fill, rounding and shape approximation tolerances. Reject invalid shapes before grading. Report actual IoU and threshold at final result, without treating IoU itself as additional points.
- **Interaction:** zoom/pinch-pan, explicit Fit, distinguish tap/drag/draw, zoom not accidentally add marker, active Outline drawing not pan; pointer, touch and keyboard-accessible controls where possible. Move between tasks without losing unsent response in same run. Stop misleading Check states when media fails; do not score without source image.

## Checking and scoring (HS-03 and HS-04)
- Every uniquely correct found target is worth 1 point; no double-award. Find One max 1, Find Multiple max = number distinct targets, Find in Order max = number canonical steps. Incorrect objects/points/contours receive no credit. Reveal correct reference zones and learner marks in final result; additionally show measured IoU/threshold for Outline.
- **Find One / Find Multiple:** shared Behavior Core 3 checks if original number of *scored target units in the applicable checking scope* is 1–5, 5 if >=6; teacher override only under approved shared control. Intermediate correct targets lock green; wrong/unmatched selections red and are editable/removable. Completeness gate: an expected count of responses should be provided before Check (except when editing known wrongs and correctly locked targets); no accidental repeated checks or duplicate credit.
- **HS-04 C — explicitly approved refinement for Find Multiple:** *final* unrepaired false-positive marks cause 1-point deduction each from unique correct-target credits, floored at zero. Formula: `max(0, min(targetCount, correctUniqueTargetCount) - remainingFalsePositiveCount)`. No negative final scores. A false mark never creates positive points, and intermediate false marks must be removable; the deduction only applies to final remaining errors. This is a Hotspot-specific penalty adjustment to the earlier generic no-negative-marking approach, not a platform-wide Behavior Core change. A student who correctly finds all N targets but leaves 1 false selection finishes with N-1 of N, not N/N. Ensure correctly locked targets aren't re-awarded; deduplicate false marks by actual distinct marked responses, and do not additionally deduct the *same* false mark as both missing and surplus. Find One/Find in Order do not take this Find Multiple deduction.
- **Find in Order — explicitly approved exception:** each sequential step has an independent check budget, default **3 checks per step** (one target). On correct choice lock 1 point and advance. On exhaustion reveal correct target, award 0 for that step and advance rather than blocking remaining steps. Step budgets do not consume a global 3/5 pool; reset restarts all budgets. If an authored sequential step ever contains multiple targets, require product definition before publish rather than silently changing the approved one-target-per-step policy.
- End state: achieved all targets or exhausted applicable checks/steps; show correct areas and learner geometry, status without color-only reliance, point totals; full reset clears markers, zone selection, drawn contours, locks, counters and session score; reshuffle only if explicitly enabled in task order design. Published exercise version pinned for active session.

## Edge cases, accessibility and performance (HS-04)
- Region boundary and tiny hotspots, overlap, near-zero shapes, polygon self-crossing, freehand jitter/smoothing, multi-contour one-to-one assignment, source image crop/letterbox, retina scaling, CSS transforms, iframe resize and device rotation all tested deterministically.
- Alt keyboard navigation for Point and Zone (focusable grid/movable marker/region picker with no exposed answer labels); Outline via successive focusable vertices and numeric coordinate adjustment. Provide teacher-authored equivalent text alternative for students unable to use visually spatial content; do not claim automatic equivalent generated from image. All interactive controls keyboard/touch capable, focus visible, status text + shape not color only, reduced motion, sufficient touch size.
- Lazy or optimized image loading without ever misaligning coordinates; handle missing image or revoked media safely; repeated Check idempotence. Support constrained mobile/tablet/desktop & LearnWorlds iframe with no horizontal overflow. Preview author desktop/mobile sizes and consider tiny zone warning. Versioned publication freezes zones/labels/media and scoring; past sessions do not mutate on author edits.
