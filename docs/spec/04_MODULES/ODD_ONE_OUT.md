# Odd One Out — модуль 05

**Статус: APPROVED DESIGN / NOT IMPLEMENTED**  
**Дата:** 2026-10-15  
**Решения:** OO-01; OO-02 A–F; OO-03 A–F; OO-04 A–D.

## Назначение
В группе учащийся выбирает ровно один лишний элемент. Одно упражнение содержит несколько групп. Один полностью правильно выбранный элемент в группе = 1 балл. Нет частичных баллов и нет сохранения результатов учеников.

## Авторский интерфейс: Content
- Группы — компактные раскрывающиеся блоки; добавление, дублирование, редактирование, удаление и перестановка (общий Editor Core). При дублировании выдаются новые стабильные ID группы и её элементов.
- Новая группа содержит три пустых элемента. Для публикации в каждой группе минимум три заполненных элемента; жёсткого верхнего предела нет.
- Каждый элемент допускает только текст, только изображение, сочетание текста и изображения, необязательное аудио. Медиа через общие Media Library / Media Viewer; ни отдельной библиотеки, ни отдельного просмотрщика.
- У каждой группы ровно один правильный «лишний» элемент. Назначается внутри группы; хранится по стабильному `itemId`, независимо от сортировки или перемешивания.
- Можно задать текст заголовка/задания для группы и необязательное пояснение. Пояснение не влияет на оценку или число проверок.
- Пустые/неполные группы разрешены в черновике; публикация блокируется с локальным сообщением о причине.
- Удаление назначенного лишнего элемента очищает правильное назначение и выводит предупреждение. Изменение/удаление других элементов и групп не меняет данные оставшихся групп. Удаление объекта из упражнения не удаляет его файл из Media Library.

## Дизайн
- Общий стиль упражнения: `chips` (плашки) или `cards` (карточки). Для каждой группы необязательная галочка «Индивидуальное оформление», раскрывающая собственный выбор из этих двух стилей.
- Если override выключен, применяется общий стиль. Прежний индивидуальный выбор сохраняется в черновике для восстановления.
- Представление меняет только оформление, не правильность или данные ответов.
- Для карточек — адаптивная сетка; для плашек — перенос строк. Длинные подписи переносятся; без горизонтального переполнения внутри iframe.

## Student Player
- Режимы отображения: одна группа с навигацией «Предыдущая / Следующая» (**по умолчанию**) либо все группы вертикальным списком. Ответы сохраняются при навигации.
- Один выбранный элемент на группу. Нажатие на другой меняет выбор; повторное нажатие на выбранный снимает выделение до закрепления.
- Выбор изображения — нажатием на карточку/плашку; отдельная иконка открывает увеличенное изображение без выбора. Аудио воспроизводится независимо, без лимитов и влияния на баллы.
- Правильные группы после проверки закрепляются. Неправильный ответ можно исправлять, пока упражнение не завершено. Проверяются все обязательные группы только когда они заполнены; попытки и завершение определяет общий Behavior Core.
- После первой выполненной проверки пояснение правильной группы доступно; для неправильной — только после успешного исправления с проверкой или завершения. При сбросе пояснения скрыты снова.
- После завершения общий Player Core может показывать правильный лишний элемент. Никакого преждевременного раскрытия до завершения, пока ошибку можно исправлять.
- Перемешивание элементов — необязательное, **включено по умолчанию**. Привязка правильности по itemId сохраняется; порядок не меняется посреди текущего прохождения.

## Проверка и особые случаи
- Совпадающие слова или изображения **разрешены**; Editor показывает ненавязчивое предупреждение, но не блокирует публикацию только из-за совпадений. Отдельные элементы имеют собственные ID даже при одинаковом содержимом.
- При отсутствии правильного назначения, менее трёх допустимых элементов, пустом обязательном содержимом или недоступном обязательном медиа публикация блокируется; черновик остаётся редактируемым.
- Сортировка элементов не должна менять правильный itemId; дублирование создаёт новые ID; удаление группы не меняет остальные.
- Мобильный Player учитывает ширину реального контейнера, включая LearnWorlds iframe; мышь и touch дают эквивалентные действия.

## Границы ответственности
Общие механизмы проверки (1–5, по умолчанию 5), закрепления, подсказок, сброса, оценки, аудио, сохранения черновика и публикации не дублируются внутри модуля. Использовать Editor Core, Player Core, Behavior Core, Design System, Media Library и Module Registry.
