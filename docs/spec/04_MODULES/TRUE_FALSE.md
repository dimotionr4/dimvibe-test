# True / False (Binary Choice) — TF-01–TF-05.2

**Статус: APPROVED DESIGN, NOT IMPLEMENTED.** Проектирование завершено 2026-10-15. Модуль наследует Editor Core, Player Core, Behavior Core, Design System, Media Library и Publication. Этот документ **не поручает Codex начинать реализацию**.

## Назначение и варианты

Модуль бинарной классификации: две категории ответа и необязательная третья. Пресеты: True / False, Fact / Opinion, Formal / Informal, Safe / Dangerous, Healthy / Unhealthy, Past / Present. Режим Custom позволяет задать собственные тексты двух кнопок. Третья категория по умолчанию Not stated, её название редактируется. В пределах одного утверждения правильным является **ровно один** из доступных вариантов. Технические ID (`a`, `b`, `c`) независимы от надписей.

Общие названия действуют на все утверждения, **если** конкретное утверждение не переопределило формат. В карточке утверждения галочка «Другой формат ответов» открывает список пресетов и Custom; при Custom показываются поля названий двух кнопок, при включённой третьей категории — третье поле. Включённость, названия и выбранный локальный пресет сохраняются при выключении галочки и восстанавливаются при повторном включении. Правильный ответ при переименовании/смене пресета сохраняет свой ID; автор видит информационное предупреждение «Проверьте правильный ответ», поскольку семантика могла измениться. Предупреждение само по себе не блокирует публикацию.

Если третья категория отключена, а правильный ответ привязан к `c`, назначение **не удаляется и не превращается** автоматически в `a` или `b`: сохраняется в черновике, публикация запрещена до устранения конфликта. Повторное включение восстанавливает прежнее назначение. Незаполненные/совпадающие тексты активных категорий (без учёта регистра и крайних пробелов) блокируют публикацию, но не редактирование.

## Author Studio / Content

Компактные раскрывающиеся строки утверждений с редактором текста и необязательным пояснением. Слева компактная иконка категории: галочка/крестик и нейтральная для третьего ответа, без T/F; для нестандартных названий иконки означают позиции категорий, а не объективную истинность, название доступно текстом/подсказкой. Внутри раскрытия — выбор одного правильного ответа, необязательное аудио каждого утверждения через общую Media Library, индивидуальный формат. Добавление, дублирование (с новым стабильным ID), удаление с подтверждением заполненной записи, изменение порядка drag-and-drop и доступными кнопками вверх/вниз. При переходе к другой строке предыдущая может сворачиваться. Счётчиков символов нет. Пустые записи допустимы в черновике, но блокируют публикацию; недостающий правильный ответ также блокирует публикацию.

`Require correction if False` виден в редакторе неактивным, с меткой **Coming soon**; нет действующего поведения в Student Player, оценивании или публикации.

## Student Player / Design

Общая настройка отображения: **по одному утверждению** (по умолчанию) с «Предыдущий/Следующий», либо **все сразу** вертикальным списком. Переключение не меняет содержание, ответы, медиа и настройки. В первом режиме навигация допускается независимо от того, заполнено ли текущее утверждение; выбор сохраняется. В обоих режимах проверяются все обязательные утверждения одновременно через общий Behavior Core, только после заполнения всех; правильные закрепляются, ошибочные можно менять до завершения. Общие лимиты проверок, прогресс, результаты, сброс и отсутствие хранения результатов не дублируются.

Пояснение пишется автором и **скрыто до первой проверки**. После проверки пояснение открывается для верно отвеченных и закреплённых утверждений. Для неправильно отвеченных оно остаётся скрытым, даже если может раскрыть правильный ответ, до успешной последующей проверки исправления либо окончательного завершения упражнения. При завершении все имеющиеся пояснения доступны. Отображение: под вариантами в одиночной карточке, под соответствующим утверждением в списке. Сброс снова скрывает пояснения. Пояснения не уменьшают баллы, не расходуют проверки и не заменяют подсказки Behavior Core.

## Публикационная валидация и инварианты

Не публиковать пустой набор, пустые утверждения, записи без активного правильного ответа, дублирующиеся/пустые подписи активных категорий, ссылки на отключённую третью категорию. Предыдущие отключённые конфигурации хранятся как черновик. Привязки к стабильным ID выдерживают перестановку, смену пресетов и текстовых подписей. Аудио опционально; отсутствие аудио не ошибка.
