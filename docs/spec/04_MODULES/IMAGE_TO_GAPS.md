# Image to Gaps — спецификация модуля

**Статус:** согласованное поведение; подробные UX-правила не должны блокировать MVP  
**Проект:** DimVibe · 2026-10-14  
**Правило:** при конфликте см. `GOVERNANCE.md` и реестр решений `DECISIONS.md`.



**Контент и банк**

- Каждый пропуск имеет назначенное правильное изображение; отвлекающие изображения собираются в общий банк упражнения.
- Общая медиабиблиотека DimVibe для повторного использования изображений между модулями.
- Одно изображение может быть правильным в нескольких пропусках: создавать отдельный экземпляр в банке на каждое требуемое размещение.
- Изображение может одновременно использоваться как правильное и как ловушка при соответствующей конфигурации.
- В Editor единая сетка банка с фильтрами «Все», «Ответы», «Ловушки»; маркировка ответов только для автора. Ученик не видит меток правильности.
- Добавление ловушек через контекст пропуска или общий банк; множественный выбор из медиабиблиотеки.
- Карточки изображений: `contain` по умолчанию, опционально `cover`; внутри пропуска изображение остаётся читаемым, элемент переносится целиком.
- Замена изображения сохраняет назначение, позицию, оформление и Undo; если изображение используется в нескольких местах, можно заменить в одном или во всех.
- Удаление назначенных изображений защищено; массовое удаление — только неназначенных с подтверждением.
- Перемешивание банка только при новом прохождении, без перемешивания во время выполнения; при «Начать заново» по ранее согласованному UX порядок банка сохраняется, но обновление страницы создаёт новое прохождение и может применить новое перемешивание.

**Действия ученика**

- Выбор доступной картинки подсвечивает все пустые пропуски одинаково, не раскрывая правильные.
- Нажатие на пустой пропуск размещает выбранную картинку; выбор сбрасывается.
- Использованная картинка остаётся на прежнем месте в банке приглушённой и недоступной; возвращается только через заполненный пропуск.
- Нажатие на заполненный пропуск без выбранной картинки возвращает изображение; с выбранной новой — заменяет в одно действие. Перетаскивание тоже поддерживает замену.
- Повторный выбор карточки, Esc или нажатие вне интерактивных элементов отменяют выбор; обычный скролл не отменяет.
- После неправильной проверки картинки остаются в пропусках и доступны для исправления до завершения. Исправление сбрасывает старую ошибочную подсветку до следующей проверки.
- Клавиатурное управление: Tab/Shift+Tab, Enter/Space, Esc; не переносить фокус автоматически неожиданным образом.
- Неполные ответы не проверяются и не расходуют попытку; повторная проверка после неудачи требует изменения ответа. На последней проверке прохождение завершается и ответы блокируются.
- Опциональное раскрытие правильных ответов после завершения: показывать правильное изображение рядом с ошибочным только для неправильных пропусков, с переключателем видимости; результат не меняется.
- «Начать заново» очищает ответы, подсветку, проверки и результат без подтверждения; фокус и скролл возвращаются к началу упражнения внутри iframe.

**Сообщения и результаты**

- Сообщения успеха/неуспеха настраиваются в Editor → Поведение → Завершение; базовое форматирование (жирный, курсив, переносы, ссылки), локализованные значения RU/EN/KA с fallback.
- Балл каждого пропуска: 1/0; общий процент рассчитывает Core.


## Границы ответственности

Собственный Module Editor и Module Player; общий Media Service и общие Core-компоненты. Лимит 10 пропусков проверяет Editor. Проверки/историю текущего прохождения считает Core.

## Архитектурное решение D-017 (APPROVED)

Самостоятельный модуль `image-to-gaps` со своими Module Editor и Module Player. Общая с Fill Blanks часть — только Shared Gap Engine и общие компоненты Core. Историческое название «режим Fill Blanks» отменено.


## ITG-01–ITG-04 — утверждённые уточнения (2026-10-15)

**Статус:** APPROVED · Проектирование модуля; не подтверждает реализацию в коде. При пересечении с ранними формулировками этого файла действуют уточнения ниже. Общие Editor Core, Player Core, Behavior Core, Design System, Media Library, Shared Gap Engine и Publication не меняются.

### ITG-01 — Author Studio / Содержание

- **A:** автор выбирает пропуск, затем нажимает на изображение — назначение применяется без дополнительного подтверждения.
- **B:** единая сетка изображений для ответов и ловушек; фильтры «Все / Ответы / Ловушки». Различие статусов видно только автору.
- **C:** одна кнопка добавления открывает общую Media Library: выбор ранее загруженных, загрузка новых и множественный выбор.
- **D:** каждое назначенное правильное изображение автоматически участвует в банке; ловушки добавляются вручную. Не требуется повторное добавление правильного изображения.
- Отмена назначения не удаляет исходный файл Media Library. Один файл может иметь независимые назначения и экземпляры в разных пропусках.

### ITG-02 — Student Player

- **A:** на всех устройствах основной путь — нажать изображение, затем пропуск; drag-and-drop мышью/касанием — альтернативный путь. Не требовать drag-and-drop для прохождения.
- **B:** использованные экземпляры остаются на тех же местах в банке, приглушаются и становятся недоступными; при возврате вновь доступны без сдвига остальных карточек.
- **C:** изображения можно заменять и переносить между незакреплёнными пропусками; вытесненный экземпляр возвращается в банк. Проверенные правильные размещения закреплены.
- Вариант **D** о закреплённой раскрываемой нижней панели для телефонов **не утверждён**. На данном этапе обычная адаптивная сетка без фиксированной панели.
- Возврат и замена не должны менять уже закреплённые ответы. Проверка, лимиты, подсказки и завершение управляются Behavior/Player Core.

### ITG-03 — размеры, сетка, адаптация

- **A:** размеры изображения в пропуске S/M/L, по умолчанию M; ориентиры для desktop: S ~76×64 px, M ~108×88 px, L ~146×116 px. Это ориентиры, а не обязательные фиксированные пиксели: фактический размер адаптируется под Player.
- **B:** настройка `contain` (по умолчанию) / `cover` размещается в Editor → «Дизайн»; способ отображения не меняет файл и ответ.
- **C:** банк использует одинаковые квадратные миниатюры и адаптивную сетку (на телефоне обычно 2–3 столбца при наличии ширины), без горизонтального переполнения.
- **D:** повторное использование не создаёт копий медиафайла; каждое обязательное размещение получает собственный экземпляр.
- **E:** адаптивность определяется шириной контейнера Player внутри iframe (в том числе LearnWorlds), а не только viewport браузера; без утверждения фиксированной мобильной панели.
- Карточки должны оставаться распознаваемыми и пригодными для касания; оптимизированные миниатюры загружаются через общую Media Library.

### ITG-04 — финальная семантика и пограничные случаи

- **A:** номера/ID экземпляров не показываются ученику. `mediaId` определяет идентичность изображения, `instanceId` — конкретную карточку банка, `gapId` — назначение пропуска. Оценивание ответа выполняется по допустимому `mediaId` для `gapId`, не по `instanceId`. Любой одинаковый экземпляр должен засчитываться одинаково.
- **B:** допускаются дополнительные экземпляры одного `mediaId`, включая конфигурацию «правильное изображение + дополнительная копия-ловушка». Editor предупреждает о повторе. В конкретном пропуске дополнительный экземпляр с правильным `mediaId` **нельзя** считать ошибочным лишь по метке «ловушка»: все копии оцениваются одинаково. Важно обеспечить достаточное число экземпляров для всех обязательных размещений.
- **C:** замена изображения в Editor по умолчанию касается только выбранного пропуска. Отдельное явное действие «Заменить во всех связанных пропусках» изменяет остальные назначения. Позиция/стили/настройки пропусков сохраняются; Undo/Redo — через общий Editor Core.
- **D:** разрешён опциональный показ правильных изображений после завершения через Editor → «Поведение»: для ошибочных пропусков изображение показывается рядом с ответом с переключателем видимости. Не меняет полученные баллы и число попыток; по умолчанию опция выключена, пока преподаватель явно не включит.
- **E:** 12 специализированных критериев `AC-ITG-01`–`AC-ITG-12` зафиксированы в `07_DELIVERY/ACCEPTANCE_CRITERIA.md`.
- Публикация блокируется при пропуске без корректного назначенного медиа, отсутствующем/недоступном ресурсе или недостаточном числе экземпляров. Авторское редактирование остаётся доступным; файл из Media Library при удалении назначения не удаляется.
- Ошибочное размещение не раскрывает правильный ответ до предусмотренного правилами Core момента. Незакреплённое изображение можно вернуть/заменить, а завершённое упражнение не редактируется.

### Не изменяется

Общая оценка один балл за пропуск, 1–5 проверок, блокировка правильных ответов, подсказки, сброс, публикация, система Classic/Comic и иные общие компоненты остаются под управлением их нормативных документов. Это решение не запускает реализацию Image to Gaps в Codex и не меняет порядок этапов разработки.
