# Multiple Choice — MC-01–MC-06

**Статус: APPROVED DESIGN, NOT IMPLEMENTED.** Проектирование завершено 2026-10-15. Ранее ABCD Exercise. Спецификация модуля; **не заказ Codex на реализацию**. Общие Editor/Player/Behavior Core, Design System, Media Library и Publication повторно не реализуются.

## Назначение и оценивание

Один модуль поддерживает **Single Choice** (один правильный вариант) и **Multiple Select** (один или несколько правильных вариантов). Возможен отдельный режим выбора для каждого вопроса; общая настройка задаёт режим по умолчанию. **Ровно 1 балл за вопрос** начисляется только когда выбран точный набор всех правильных вариантов без лишних; частичных баллов нет. Один и тот же вопрос имеет максимум один балл, даже если правильных вариантов несколько. Проверяется через Behavior Core, после ответа на каждый обязательный вопрос (минимум один выбранный вариант; точное число ответов не требуется заранее).

Вариантам автоматически назначаются видимые метки `A, B, C…` **или** `1, 2, 3…`, выбор на всё упражнение. Метка зависит от текущего порядка, правильность — от стабильного optionId. Можно включить перемешивание вариантов (по умолчанию **включено**): порядок стабилен во время прохождения, сброс текущего прохождения его не меняет; новая загрузка может заново перемешать. Опциональная инструкция «Выберите N правильных ответов» (по умолчанию **выключена**) видна сразу при включении и не является Behavior Core hint.

Переход Single ↔ Multiple не уничтожает старые назначения; при конфликте нескольких правильных в Single черновик остаётся редактируемым, но публикация блокируется до выбора одного активного. Возврат в Multiple восстанавливает сохранённые назначения. В Multiple разрешено, чтобы все предложенные варианты были правильными.

## Author Studio / Content

Вопросы — компактные раскрывающиеся карточки с inline редактированием текста, добавлением, дублированием (новые ID), удалением, drag-and-drop и перемещением кнопками. Каждый вопрос содержит собственные варианты, собственный single/multiple режим, правильные optionId, медиа вопроса и медиа каждого варианта. По умолчанию четыре варианта, **минимум два при публикации**, жёсткого максимума нет. Редактирование пустых/неполных черновиков разрешено; публикация требует заполненный вопрос, заполненные обязательные варианты и допустимые правильные назначения. Перемещение не меняет ID, правильность или медиа.

Варианты могут быть текстовыми, графическими или смешанными (изображение с необязательным текстом). Изображение и аудио допускаются отдельно для вопроса и для каждого варианта через общую Media Library/аудиосервисы. Каждому вопросу можно назначить собственную главную картинку как часть вопроса; её положение относительно текста — **сверху (по умолчанию), снизу, слева, справа**, с использованием общего механизма layout медиа инструкции и его настроек размера/fit. Изображения вариантов независимы от положения главной картинки. Боковое расположение адаптируется на узких экранах без горизонтального скролла.

## Student Player / Design

Два режима показа: **один вопрос с навигацией** (по умолчанию) или **все вопросы вертикальным списком**. Выбор и медиа остаются при навигации/переключении отображения. Single Choice заменяет предыдущий выбор; Multiple Select переключает выбранность каждого варианта. Текстовые варианты располагаются читаемым списком, графические — адаптивной сеткой, смешанные — адаптивно без потери читаемости. Клик карточки выбирает ответ; отдельная иконка увеличивает картинку без изменения выбора. Допускается опциональное увеличение при наведении мышью, для touch используется иконка. Большой просмотр поверх Player через общий Media Viewer, **без отдельной вкладки браузера как обязательного пути**. Аудио вопроса и отдельных вариантов воспроизводится независимо, без влияния на выбор и оценки.

Правильный вопрос закрепляется после проверки, неправильный допускает изменения до следующей проверки/окончания попыток. Для ошибочного Multiple Select **не раскрывать**, какой из отмеченных отдельных вариантов был правильным: показывать неверность всего вопроса. После завершения допустим показ правильного набора через общий результат Player. Все вопросы проверяются одновременно, незаполненный обязательный вопрос не расходует попытку. Лимиты, сброс, подсказки, финал и результаты — общий Behavior Core, без сохранения результатов учеников.

## Будущие общие инструменты

`AI Scanner` и `Smart Import` отложены и относятся к будущим общим возможностям Author Studio для нескольких модулей, **не к MVP Multiple Choice**.

## Границы и приёмка

Публикация блокируется при <2 вариантов, отсутствии правильного, нескольких правильных в активном Single, пустом вопросе/обязательном варианте, недоступном необходимом медиа; предупреждение не удаляет черновик. При удалении правильного варианта проверить допустимость оставшихся назначений. Отсутствие необязательного медиа само по себе не ошибка. Узкий iframe и сенсорные экраны сохраняют удобный доступ к вариантам, медиа и кнопкам.

Принято MC-06 A–D: защита неправильного набора от частичного раскрытия, итоговое отображение верного набора через общие результаты, сохранение конфликтующих данных и **18 сценариев приёмки** `MC-AC-01–18` в `07_DELIVERY/ACCEPTANCE_CRITERIA.md`.
