# Module 16 — Essay Writing (EW-01–EW-04)

**Status:** Functional design approved for EW-02 A–F, EW-03 A–F, EW-04 A–F. **EW-01 A–F were recommended and discussed but not explicitly approved by an EW-01 vote.** Preserve that boundary: the concepts repeated in the approved later stages are approved within those stages; all other EW-01-only ideas remain provisional. Specification only; NOT a Codex task. Date: 2026-10-16.

## 1. Product goals and boundaries
Write essays, descriptions, letters, stories, summaries and other free-text compositions against teacher-configured constraints. Formally measurable compliance MUST be differentiated from semantic/linguistic quality. Never label percentage of fulfilled formal requirements as an essay quality grade. Avoid requiring AI or paid APIs. Use shared Editor/Player/Design/Publication Core, and a specialized Text Analysis Core with deterministic versioned language profiles. Author Studio desktop-only; Student Player responsive and usable within LearnWorlds iframe.

## 2. Author Studio (approved EW-02)
- Teacher authors topic, meaningful prompt, optional instructions/materials, exercise language, word/sentence/paragraph minimum/maximum, required/prohibited vocabulary, per-entry minimum occurrences, exact words/phrases and teacher-listed accepted inflections. Optional composition structure requirements and timer; never pretend logical quality of introduction/conclusion can be accurately inferred from raw text without explicit structural fields or human review.
- Each machine-checkable requirement has a stable ID, thresholds, status required/advisory and explicit checker configuration. Nonobjective instructions are shown but are never used as automatic Strict blockers. Drafts may remain incomplete; incompatible/contradictory publish configuration blocks publication.
- Practice: self-guided writing and formal-condition feedback without server submission or automatic semantic grading. Submission: server-backed identifiable assignment and authenticated/secure submission channel; if such infrastructure is unavailable, hide/disable Submission rather than simulate success.
- Teacher selects Strict or Flexible (**Flexible default**). Strict blocks submission on failed objectively checkable REQUIRED requirements only; advisory requirements never block. Flexible allows submission with explicit summary/warning and confirmation, with failed requirements recorded. Neither rule forbids typing while a limit is exceeded.
- Configurable teacher grading rubric with independent named criteria, maxima, score limits, comments, draft review and controlled publication. Teacher may assess meaning, grammar, vocabulary, coherence, style. Two results independent: machine-checked compliance and teacher quality grade. No combined score or AI grading by default; combining would require further approval.
- Submission ownership constrained to the teacher's own exercises/assigned submissions, and full admin privileges. Authenticated review/result retrieval; no public result exposure via iframe.

## 3. Text Analysis Core (approved EW-04)
- Deterministic, language-profile-versioned tokenization for word boundaries, Unicode, apostrophes, hyphens, numbers (configurable inclusion), contractions/abbreviations, sentence boundaries, punctuation, and nonempty paragraph blocks. Unicode normalize for matching without overwriting original submitted text. Client and server MUST use equivalent algorithm/profile versions or server's authoritative re-evaluation to avoid mismatched counts.
- Word counts are unrelated to visual line wrap and must match on desktop/mobile/iframe. Explain language-specific conventions, especially where whitespace does not mark lexical boundaries. Prevent splitting sentences at common abbreviations such as `Dr.`/`e.g.` where the chosen profile recognizes them. Do not claim perfect grammatical sentence recognition; surface the counting rules transparently.
- Required vocabulary uses true lexical boundaries (e.g. `art` not inside `article`/`smart`), language-appropriate caseless comparison, phrase-token sequencing/normalized intervening whitespace, explicit teacher-approved form alternatives, and minimum occurrences. One instance counted at most once per specific requirement; no accidental duplicate matches. Prohibited vocabulary uses compatible boundary rules. Required-vs-prohibited irreconcilable overlap is a publish blocker. Single-letter/phrase punctuation/Unicode edge cases are tested. Preserve exact text for audit.
- Each submission stores immutable analysis snapshot (counts, per-requirement results, profile/version, prompt version) and unmodified text. Future checker updates never silently change historical results or published teacher grades.

## 4. Student Player: Practice and Submission (approved EW-03)
- Accessible plain-text rich enough for paragraphs (no uncontrolled HTML execution); live counts, fulfillment status, required terms, clear missing/over-limit indications; responsive/mobile and iframe-compatible. Never block typing for limit violations. Allow viewing prompt and instructions while writing, copying text, and accessible focus/non-color status.
- Local draft save/recovery if platform/browser policy permits, with explicit degradation warning if storage denied. Submission synchronizes drafts to server in authorized secure session. Server-confirmed `Saved` status only after positive acknowledgement. Conflict detection across tabs/devices with recovery strategy preventing silent overwrite; offline warning, retry and copy text option. Sensitive drafts not sent in URL/analytics/logging.
- Submission state machine: editing -> optional preview/condition review -> confirm -> pending network ack -> accepted immutable submitted attempt -> awaiting teacher review -> reviewed/unpublished -> published result. Offline/timeout does not equal accepted; idempotent retry + server look-up resolve ambiguous network result, no duplicate attempts. Submitted text and compliance snapshot immutable; explicit teacher-authorized resubmission creates a new attempt and retains previous version.
- Timer optional. For authenticated Submission use server time/deadline as authority; on expiry stop new editing under exercise policy and finalize only acknowledged text. Allow technical save/transport grace without granting extra writing time. Do not falsely promise offline auto-submission; submission validity is server-confirmed.
- After Practice, report check results (X/N) and enable revision, copy and finish; no fake semantic grade. After Submission, show verified receipt ID/status and compliance, teacher quality result pending. When teacher publishes rubric marks and feedback, learner sees them through protected authorized channel. A zero grade and an ungraded assignment are clearly different.

## 5. Behavior and scoring — explicit exception
- Essay Writing does **not** use gap/object 3/5 automatic checking loops, their automatic scoring units or locking behaviors. Live requirement checking may run repeatedly while typing; each check recomputes formal compliance and does not award automatic essay-quality points.
- Formal fulfillment X/N can include required+advisory criteria, visibly separated; it is not by itself a grade. Server validates objective requirements and submission eligibility at final confirmation (to prevent stale client data or forged requests).
- Teacher rubric scores are not considered final/published until the teacher explicitly publishes. No automatically fused score. A teacher's revised rubric does not rewrite existing published results without an explicit audited action.
- Submission drafts and attempts use safe, idempotent mutation APIs with access checks and no duplicate outcome on double-click/retry. Historical state is protected.

## 6. Validation and security edge cases (approved EW-04)
- Block invalid min>max, impossible constraints, directly contradictory vocabulary, invalid/non-unique criterion IDs, insecure Submission config, or missing meaningful prompt. All requirements off is a valid free-writing activity if prompt exists.
- Whitespace-only response is empty, cannot count as meaningful submission. Maximum payload/length protects performance; explicit errors and loss-prevention for paste oversize. Warn rather than silently truncate. Number/emoji handling follows versioned language config.
- Session identity by actual authorization or controlled submission session, not name field. Teacher visibility scoped to own students' submissions; admin within platform-wide rights. Enforce server-side authorization on create/read/edit/review/result API routes; encryption/security standards per project architecture. Avoid PII in URLs and logs. Data export, retention/deletion and teacher feedback publishing must obey platform permissions/policy.
- Version exercise requirements on submission; later edits do not affect prior snapshots. All errors, reconnection and tab conflicts tested. UI cannot show 'submitted' before confirmed persisted state.

## 7. Design integration
Inherit Classic/Comic, Compact/Standard and accessible player states, adaptive text editor, no fixed widths, proper behavior under narrow LearnWorlds iframe. Author Studio remains desktop-only. Submission requires real backing service; do not invent LMS integration to infer learner identity from an untrusted frame.
