# Хранение данных DimVibe — проект спецификации

**Статус: MIXED — модель B (личные аккаунты и библиотеки) APPROVED; детали хранения PROPOSED.** Это предлагаемая реализация утверждённых функций MVP; провайдер, БД, API и авторизация ещё не утверждены. Обязательные инварианты публикаций принадлежат `05_PUBLICATION/PUBLICATION.md`.

## Границы

- **Exercise**: `id`, `ownerId` (обязательно: модель B утверждена), `module`, метаданные (название, даты, статус). ID стабилен независимо от публикаций.
- **Draft**: редактируемый документ упражнения с `schemaVersion`, `content`, `design`, `behavior`, `moduleData`, ссылками на media IDs; `draftRevision` для защиты от случайного перезаписывания. Восстанавливается после закрытия Editor.
- **PublishedVersion**: immutable snapshot со своим `versionId`, `exerciseId`, `versionNumber`, `schemaVersion`, временем публикации, полным payload и ссылками на фиксированные media assets. Не изменяется после создания.
- **PublicationPointer**: `exerciseId → publishedVersionId`; при откате меняется только указатель.
- **MediaAsset**: `assetId`, owner/scope, storage key, MIME, размер, размеры изображения, время создания; **не** бинарное изображение внутри JSON упражнения.
- **EditorPreferences**: язык интерфейса, тема и прочие персональные настройки, не влияющие на публичную версию. Отделить от exercise `design`.
- **PlayerSession**: только оперативная память вкладки/iframe. Не сохранять ответы, историю проверок и результаты после reload.

`publication` в общей схеме упражнения описывает настройки/метаданные публикации; авторитетный `publishedVersionId` хранится отдельно от редактируемого Draft, чтобы черновик не мог переключать активную публикацию при сохранении.

## Предлагаемые интерфейсы репозиториев (не окончательные API)

- `ExerciseRepository`: create/list/get/duplicate/softDelete.
- `DraftRepository`: load/save with expectedRevision; server validates schema and ownership.
- `PublicationRepository`: publishDraft, getActivePublished, listVersions, rollback.
- `MediaRepository`: upload/list/getMetadata/resolvePublicAsset.

Core и модули вызывают абстракции через сервисный слой, не импортируют Firebase SDK/SQL напрямую. Backend-права должны проверяться сервером, а не только скрытием кнопок.

## Атомарность и конкуренция

1. Сохранение черновика с ожидаемой ревизией; конфликт двух вкладок возвращает явное уведомление, не молча затирает данные.
2. Публикация проверяет актуальный Draft и его ссылки на медиа, создаёт неизменяемый снимок и атомарно переключает активный указатель.
3. При сбое создания/валидации указатель остаётся прежним.
4. Player получает согласованный snapshot и не перечитывает его в ходе одного прохождения.
5. При дублировании упражнения создаются новые exercise/draft IDs; опубликованные версии исходника не перезаписываются. Публикация копии отдельно.

## Удаление (предложение)

Для MVP рекомендовано **soft delete** упражнения из библиотеки автора; не удалять автоматически опубликованные версии и используемые ими медиа. Для уже опубликованного упражнения нужна явная политика публичной ссылки: оставить доступной / снять с публикации / показывать страницу недоступности. **OPEN, требуется выбор пользователя.**

## Медиа и неизменяемость

Опубликованная версия должна ссылаться на неизменяемые байты изображения (asset ID с immutable content или asset revision/hash). Замена изображения в медиабиблиотеке не должна незаметно изменять старые публикации. Удаление медиа, используемого Draft или публикацией, блокируется или выполняется только после явного управления ссылками. При публичном Player обеспечивать разрешённый доступ к изображениям без доступа к приватным черновикам.

## Безопасность и технические ограничения (требуют конкретизации)

Валидация схемы на сервере; лимиты файлов/типов/размеров; защита от XSS в rich text; контроль прав автора; проверка URL/embed; резервные копии и миграции схем. Не считать наличие этих мер реализованным без тестов.

## Не хранить в MVP

Ответы учеников, состояние банка при прохождении, историю нескольких прохождений, gradebook/аналитику, sessionStorage-восстановление.
