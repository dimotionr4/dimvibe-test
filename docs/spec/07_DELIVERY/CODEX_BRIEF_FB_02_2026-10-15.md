# Задание для Codex — FB-02 (подготовлено, НЕ запускать без передачи в Development)

**Репозиторий:** `C:\PROJECTS\DimVibe`, одна общая кодовая база. **Цель:** реализовать только недостающие части утверждённых механик Fill Blanks FB-02.1–02.4, без пересоздания Editor/Player/Behavior Core.

## Перед изменениями
1. Изучи `GOVERNANCE.md`, `DECISIONS.md`, `04_MODULES/FILL_BLANKS.md`, `07_DELIVERY/ACCEPTANCE_CRITERIA.md` и текущие реализации Fill Blanks/Gap Engine.
2. Сообщи фактический `git status`, HEAD, текущее покрытие Free Input / Word Bank / Dropdown, состояние сохранения Draft и недостающие участки. Наличие функциональности в коде **не предполагается**.
3. Не переписывай работающие функции и не меняй механизм хранения результатов учеников (они не должны сохраняться).

## План внедрения: маленькие проверяемые изменения
1. Проверить/дополнить единые данные пропусков и режимные настройки, сохранив `gapId`, основные/альтернативные ответы и старые Draft через совместимую миграцию (если необходима). Не ломать сохранённые данные.
2. Реализовать автопул основных ответов Word Bank, ручные ловушки через `+ Добавить слово`, явные экземпляры альтернатив, независимые ID дублей.
3. Реализовать Player Word Bank: выбрать-нажать, mouse/touch drag-and-drop, занятые слова не исчезают и не сдвигают банк, перенос между незакреплёнными пропусками, возврат заменённых слов. Учесть блокировки Behavior Core.
4. Реализовать Dropdown: общий пул из основных ответов всех пропусков, альтернатив и ловушек; отдельная корректность для каждого gap ID; дедупликация вариантов только по отображаемому тексту; 2+ различных варианта с минимум одним правильным и одним неправильным, предупреждение >8, блок публикации невалидного активного режима.
5. Переключение Free Input / Word Bank / Dropdown: не удалять скрытые настройки и ответы; проверить сохранение/восстановление и изоляцию Preview.
6. Проверь UX desktop Editor и responsive Player на узком мобильном экране, мышь/сенсорное управление и клавиатуру; не добавлять мобильный Editor.

## Не менять
- Image to Gaps, Registry/Publication/Media Library как самостоятельные подсистемы, общие правила оценивания, лимитов проверок, подсказок и озвучки.
- Не создавать отдельный репозиторий, модульное приложение или новую систему autosave.
- Не публиковать автоматически, не делать деплой без явного задания.

## Проверка готовности
- Выполнить AC-FB-01–AC-FB-13 вместе с существующими AC-16–AC-20, тесты/lint/build и необходимые regression tests для Gap Engine/Behavior Core.
- Если нет среды браузерной проверки — честно указать непроверенное, не выдавать за проверенное.
- В отчёте: перечислить реальные изменённые файлы, тесты и результаты, миграции/совместимость, нерешённые вопросы, git HEAD/status.

**Важно:** это план полного FB-02, а не требование выполнить весь объём одним гигантским коммитом. Начни с аудита кода и согласования минимального первого изменения в чате Development.
